Architecture & Real-time Chat

How a request flows from the React SPA through the role-scoped Web API, the DAO repositories and EF Core to SQL Server — plus the SignalR path that powers live coach ↔ member chat over a WebSocket.

System Architecture

layered · stateless JWT

Two transports reach the backend: ordinary REST calls (JSON + Authorization: Bearer) and a SignalR WebSocket for chat (JWT passed as ?access_token because browsers can't set headers on a socket). Both share the same auth, the same repositories and the same EF Core context. The connection string is built once by the Singleton DatabaseConfig.

Real-time Chat — Sequence

SignalR · send + push

Sending one message: the member's client invokes the hub over the open socket; the hub authorizes via ChatDirectory, persists through MessageRepository, then pushes a ReceiveMessage event to the recipient and echoes it back to the sender. No polling — each client just reacts to the event.
